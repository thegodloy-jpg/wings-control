# MiniMax-M2.7 开源 vLLM 0.19 部署方案 (NVIDIA GPU)

> 状态：历史专项记录。当前正式部署口径请以 [../README.md](../README.md)、[../docs/deployment/docker-compose.md](../docs/deployment/docker-compose.md) 和 [../docs/deployment/k8s.md](../docs/deployment/k8s.md) 为准；`wings_start.sh` 支持的启动项优先使用 CLI 字段。

> 来源：[MiniMaxAI 官方 vLLM 部署指南](https://huggingface.co/MiniMaxAI/MiniMax-M2.7/blob/main/docs/vllm_deploy_guide.md)

## 模型信息

| 项目 | 值 |
|------|-----|
| HuggingFace 模型 ID | `MiniMaxAI/MiniMax-M2.7` |
| 模型架构 | `MiniMaxM2ForCausalLM` |
| 参数量 | ~229B (MoE) |
| 权重体积 | ~220 GB |
| 每 1M context tokens 额外显存 | ~240 GB |
| 最大单序列上下文 | 196K tokens |

## 环境安装

```bash
uv venv
source .venv/bin/activate
uv pip install vllm --torch-backend=auto
```

## 启动命令

### 4 卡部署 (96G×4, 支持 ~400K tokens 总 KV Cache)

```bash
SAFETENSORS_FAST_GPU=1 vllm serve \
    MiniMaxAI/MiniMax-M2.7 --trust-remote-code \
    --tensor-parallel-size 4 \
    --enable-auto-tool-choice --tool-call-parser minimax_m2 \
    --reasoning-parser minimax_m2_append_think
```

### 8 卡部署 (144G×8, 支持 ~3M tokens 总 KV Cache)

```bash
SAFETENSORS_FAST_GPU=1 vllm serve \
    MiniMaxAI/MiniMax-M2.7 --trust-remote-code \
    --enable_expert_parallel --tensor-parallel-size 8 \
    --enable-auto-tool-choice --tool-call-parser minimax_m2 \
    --reasoning-parser minimax_m2_append_think
```

## 验证部署

```bash
curl http://localhost:8000/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{
        "model": "MiniMaxAI/MiniMax-M2.7",
        "messages": [
            {"role": "system", "content": [{"type": "text", "text": "You are a helpful assistant."}]},
            {"role": "user", "content": [{"type": "text", "text": "Who won the world series in 2020?"}]}
        ]
    }'
```

## 关键参数说明

- `--trust-remote-code` — **必须**，M2.7 使用自定义模型类
- `--tool-call-parser minimax_m2` — MiniMax M2 专用的 function calling 解析器
- `--reasoning-parser minimax_m2_append_think` — M2.7 推理思考链解析器
- `--enable_expert_parallel` — 8 卡时开启专家并行
- `SAFETENSORS_FAST_GPU=1` — 加速权重加载

## 推荐推理参数

- `temperature=1.0`
- `top_p=0.95`
- `top_k=40`

## 常见问题

| 问题 | 解决方案 |
|------|---------|
| "MiniMax-M2 model is not currently supported" | vLLM 版本过旧，需升级到最新版 |
| CUDA error: illegal memory access | 添加 `--compilation-config "{\"cudagraph_mode\": \"PIECEWISE\"}"` |
| 输出乱码 | 升级到 nightly 版本 (cf3eacfe58fa 之后的 commit) |

## 社区 Open Issues (截至 2026-04-19)

以下是 vLLM 主仓库中与 MiniMax-M2/M2.5/M2.7 相关的未关闭 issue，部署前需关注：

| Issue | 标题 | 影响 | Workaround |
|-------|------|------|------------|
| [#38212](https://github.com/vllm-project/vllm/issues/38212) | **MiniMaxM2ReasoningParser broken for M2.5** — `minimax_m2_append_think` 不处理 `<think>` 开始标签，reasoning 泄漏到 content | 中 — 影响 reasoning 输出 | 改用 `--reasoning-parser deepseek_r1` 或 `minimax_m2`（已有 PR#38213 修复，未合并） |
| [#39649](https://github.com/vllm-project/vllm/issues/39649) | **minimax_m2_tool_parser 不流式传输 tool call args** | 低 — tool call 参数不流式输出 | 无 |
| [#39567](https://github.com/vllm-project/vllm/issues/39567) | **minimax_m2_tool_parser 将 none-like 字符串推断为 Python None** | 低 — 特殊边缘情况 | 无 |
| [#38713](https://github.com/vllm-project/vllm/issues/38713) | **MiniMax M2.5 在 4 H100 nodes 多节点部署报错** | 中 — 多节点场景 | 使用单机多卡 |
| [#37988](https://github.com/vllm-project/vllm/issues/37988) | **minimax-m2.5 reasoning token 出现负值** | 低 | 无 |
| [#37946](https://github.com/vllm-project/vllm/issues/37946) | **Minimax-M2.5 在 v0.17 上 PP>=2 时 KeyError** | 低 — v0.17 问题，v0.19 可能已修复 | 避免 PP 或升级 |

**关键结论**：
- reasoning-parser 最稳妥的选择是 `deepseek_r1` 而非 `minimax_m2_append_think`（社区反馈 deepseek_r1 对 M2.5/M2.7 兼容性最好）
- 单机多卡部署最稳定，多节点有 open bug
- tool call 的流式传输有已知 bug，但不影响非流式使用
